# Target architecture

## Product hierarchy

Tehkarta models teaching as a hierarchy:

1. Course
2. Section
3. Lesson
4. Lesson stage
5. Tasks and materials

## Source-of-truth hierarchy

The platform combines four layers:

1. **Curriculum / working program** — mandatory content, results, hours and sequence.
2. **UMK content pack** — textbook, method guide, atlas, assessments and other licensed materials.
3. **Teacher decisions** — pedagogical profile, approved goals, methods, techniques, forms and edits.
4. **AI methodologist** — proposes implementations but cannot silently overwrite approved teacher decisions.

## Approval invariant

Every important editable field has provenance and approval state:

- PROPOSED — generated by AI or loaded from a source;
- EDITED — changed by the teacher but not yet applied;
- APPROVED — explicitly applied by the teacher.

Downstream generation consumes only approved teacher-controlled values plus mandatory curriculum/UMK evidence.

## Yandex Cloud target

- Web: Object Storage + CDN
- API: Serverless Containers behind API Gateway
- Worker: Serverless Containers
- Database: Managed PostgreSQL + pgvector
- Files: Object Storage
- Async jobs: Message Queue
- Secrets: Lockbox
- Observability: Monium / OpenTelemetry
- Infrastructure as code: Terraform

## AI

All providers implement `AIProvider`. Initial benchmark routing may use OpenRouter; Yandex AI Studio is added as a first-class provider. Models are routed by task rather than using one heavyweight model for every operation.
